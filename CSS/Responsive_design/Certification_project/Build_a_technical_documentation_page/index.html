Introduction

Bash (Bourne Again SHell) is a command language interpreter for the GNU operating system. It is widely available on various versions of Unix and is the default shell on most Linux distributions and macOS. Bash can be used both as an interactive login shell and as a scripting language to automate tasks.

Bash provides a rich set of built-in commands, control structures, and features such as command history, job control, aliases, and shell functions. It can be extended for a variety of purposes; for example:

  • Interactive use: Bash serves as the user's command interface to the operating system, allowing you to run programs, manage files, and control processes directly from the terminal.
  • Shell scripting: Bash scripts automate repetitive tasks, system administration, file processing, and complex workflows by combining commands into reusable programs.
What you should already know

This guide assumes you have the following basic background:

  • A general understanding of operating systems and the concept of a file system with directories and files.
  • Basic familiarity with using a terminal or command prompt.
  • Some experience with any programming language is helpful but not required. If you are new to programming, Bash is a great place to start for system automation tasks.
Bash and Shell

Bash is one of many available Unix shells. While the original Bourne Shell (sh) established the foundation, Bash extends it with features like command-line editing, command history, and improved scripting constructs. Other popular shells include Zsh, Fish, and Ksh, each with their own syntax and features.

Unlike compiled languages, Bash scripts are interpreted at runtime, meaning the shell reads and executes each line sequentially. Bash is dynamically typed — variables do not have explicit types, and values are treated as strings by default. Arithmetic operations require special syntax to be evaluated numerically.

Bash is a very flexible language compared to compiled alternatives. You do not need to declare variable types, import libraries for basic operations, or compile your scripts before running them. However, this flexibility also requires careful attention to quoting and whitespace, which have significant meaning in Bash.

Hello world
To get started with writing Bash, open a terminal or create a new file with a .sh extension and write your first "Hello world" Bash script: #!/bin/bash echo "Hello, World!" Save the file as hello.sh, make it executable with chmod +x hello.sh, and run it with ./hello.sh to see the output in your terminal!
Variables

Variables in Bash are used to store data that can be referenced and manipulated throughout a script. Variable names are case-sensitive and can contain letters, numbers, and underscores, but must begin with a letter or underscore.

By convention, environment and shell variables are written in uppercase (e.g., PATH, HOME), while local script variables are written in lowercase. There must be no spaces around the = sign when assigning a value.

To reference the value of a variable, prefix its name with a dollar sign ($). It is good practice to enclose variable references in double quotes to prevent word splitting and globbing issues, for example: "$my_var".

Declaring variables
You can declare and assign variables in several ways:

By direct assignment. For example, name="Alice". This creates a local shell variable available within the current script or session.

Using the declare built-in. For example, declare -i count=10. This allows you to specify attributes such as integer (-i), read-only (-r), or array (-a).

Using command substitution. For example, today=$(date +%F). This assigns the output of a command to a variable, which is a very common Bash pattern.

Variable scope

In Bash, variables are global to the script by default. A variable defined in the main body of a script is accessible inside functions unless explicitly declared as local.

To limit a variable's scope to a function, use the local keyword inside the function body:

my_function() { local local_var="I am local" echo "$local_var" } my_function echo "$local_var" # prints nothing — out of scope

Variables exported with the export command become environment variables and are inherited by child processes spawned from the current shell.

Environment variables

Environment variables are special variables that are available to all processes running in the current shell session and its children. Common built-in environment variables include:

  • $HOME — the current user's home directory.
  • $PATH — a colon-separated list of directories searched for commands.
  • $USER — the name of the current user.
  • $PWD — the present working directory.
  • $SHELL — the path to the current shell.

You can view all environment variables with the env or printenv commands, and set new ones using export MY_VAR="value".

Constants

Bash does not have true constants in the way compiled languages do, but you can create read-only variables using declare -r or the readonly built-in. Once set, these cannot be modified or unset.

You cannot redeclare a read-only variable in the same shell session. For example:

readonly MAX_RETRIES=5 MAX_RETRIES=10 # This will cause an error: readonly variable However, read-only only applies to the current shell process. Child processes and subshells do not inherit the read-only attribute, only the value (if exported). declare -r PI=3.14159 echo "The value of PI is $PI"
Data types

Bash is an untyped language by default — all variables store strings. However, Bash supports several special variable types that can be declared with declare:

  • Common variable types:

    • String (default). All variables are strings unless specified otherwise.
    • Integer. Declared with declare -i; arithmetic is automatically evaluated.
    • Array. Declared with declare -a; stores an indexed list of values.
    • Associative Array. Declared with declare -A; stores key-value pairs (requires Bash 4+).
    • Read-only. Declared with declare -r or readonly; the value cannot be changed.
  • and Boolean (simulated with strings "true"/"false" or exit codes 0/1)
Although Bash's type system is minimal, these constructs allow you to write robust scripts. Arrays are especially powerful for handling lists of files, arguments, or configuration values.
if...else statement
Use the if statement to execute commands when a condition is true. Use the optional else clause to handle the false case. An if statement looks as follows: if [ condition ]; then statement_1 else statement_2 fi

You may also chain conditions using elif to test multiple cases in sequence, as follows:

if [ condition_1 ]; then statement_1 elif [ condition_2 ]; then statement_2 elif [ condition_n ]; then statement_n else statement_last fi Only the first condition that evaluates to true will have its block executed. Always ensure there is a space inside the brackets of a test expression, as [ condition ] is actually a command in Bash. if [ "$score" -ge 90 ]; then echo "Grade: A" elif [ "$score" -ge 75 ]; then echo "Grade: B" else echo "Grade: C or below" fi It is advisable to always quote variable references inside test brackets to avoid errors from empty or multi-word values. For example, prefer [ "$name" = "Alice" ] over [ $name = "Alice" ].
while statement
A while statement executes its commands as long as a specified condition evaluates to true. A while loop looks as follows: while [ condition ]; do statement done If the condition becomes false, the loop stops executing and control passes to the statement following done.

The condition is tested before each iteration. If it is true, the body executes and the condition is tested again. If it is false from the start, the body never executes.

Use break to exit a loop early and continue to skip to the next iteration.

Example:

The following while loop counts from 0 to 2:

n=0 x=0 while [ $n -lt 3 ]; do n=$((n + 1)) x=$((x + n)) done

With each iteration, the loop increments n and adds it to x. Therefore, x and n take on the following values:

  • After the first pass: n = 1 and x = 1
  • After the second pass: n = 2 and x = 3
  • After the third pass: n = 3 and x = 6
Function declarations
A function definition in Bash consists of a name followed by parentheses and a block of commands enclosed in curly braces. Functions help organize scripts into reusable units. A function declaration looks like:
  • The name of the function.
  • Empty parentheses () after the name (Bash functions do not list parameters here).
  • The commands that define the function body, enclosed in curly brackets { }.

For example, the following code defines a simple function named greet:

greet() { local name="$1" echo "Hello, $name!" }

Arguments are passed to functions positionally and accessed inside the function as $1, $2, etc. The function is called by name, followed by any arguments:

greet "Alice"

Functions can return an exit status (0–255) using the return statement. To return a string value, use echo inside the function and capture the output with command substitution.
